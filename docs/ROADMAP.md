# 開発順序と設計

## 第1段階（今回）

手動登録 → MP4抽出 → 根拠付きメモ・関係記録 → 比較・CSV出力。Streamlit / SQLite / ffmpegで単一環境で動かします。ネットワークから動画をダウンロードするコード、APIキー、AI通信は含めません。TikTok公式oEmbedによる説明文・投稿者名の取得は追加済みです（対象URLの実接続確認済み。説明文・投稿者名が返らずプレーヤー情報のみ返る応答にも対応）。登録時刻はUTCです。

画面とストレージ、動画処理、外部連携境界を分離しました。SQLは値をパラメーター化し、動画保存名はUUIDと固定ファイル名を使います。ffmpegはシェルを介さず、入力プロトコルをローカルファイルに限定してタイムアウトを設けています。機密ファイルと動画はGit管理しません。CSVの数式を開始する文字は先頭にアポストロフィを付けます。

## 次の開発順序

1. **調査データの運用改善**：編集・削除・重複警告、出典取得日時、バックアップ／復元、相対パス化。必要に応じて認証・利用者ごとの分離。
2. **公式API連携**：まずYouTubeの取得可能な公開情報から開始。続いてTikTok・Xの公式APIについて、利用資格、対象エンドポイント、費用、保存・再配布条件、レート制限を確認。対応していない情報は未取得のままにする。API接続の前に取得項目と送信先を説明して承認を得る。ログイン・CAPTCHA・アクセス制限を回避しない。
3. **ローカル解析**：カット検出、音声書き起こし、OCRを追加。ライセンス・計算資源・モデル配布条件を確認。誤認識と手動修正、タイムスタンプを保持する。
4. **AI分析**：送信データ、送信先、料金、保持条件を提示し、承認後に接続。APIキーは環境の安全な設定に保存。抽出事実、モデルの推論、未取得を分け、根拠となる動画秒数や投稿URLを必須とする。企画案は推測として扱う。
5. **横断比較・企画案生成**：比較可能な指標やサンプルの偏りを示す。再生数の多寡だけで因果や成功を断定しない。Xの投稿・リプライ・販売導線は公開情報と根拠を辿れる形で表示し、不正や組織性を根拠なく判定しない。
6. **定期収集・レポート**：公式API上限に従うキュー、再試行、取得履歴、収集停止、日次レポート、通知の送信前確認を実装。
